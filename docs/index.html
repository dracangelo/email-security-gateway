email-auth-gateway

Enterprise-grade, multi-tenant email security gateway. Pre-delivery inspection with SPF/DKIM/DMARC authentication, content and URL analysis, attachment scanning, AI-driven decision scoring, and encrypted quarantine — all in a single deployable service.

🐍 Python 3.11+ ⚡ FastAPI 🔐 Fernet Encryption ☸️ Kubernetes-Ready 📊 Prometheus ✅ 165 Tests

What it does

Every inbound email passes through three parallel analysis stages before the decision engine assigns a routing action:

0–29
FORWARD
Relay message as-is to destination
30–69
WARN & STRIP
Prefix subject, defang URLs, strip attachments
70+
QUARANTINE
Encrypt, store, notify — admin reviews

Quick Start

1. Install

git clone https://github.com/your-org/email-auth-gateway.git
cd email-auth-gateway
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

2. Configure

cp .env.example .env

# Generate secrets
WEBHOOK_SHARED_SECRET=$(python3 -c "import secrets; print(secrets.token_urlsafe(32))")
RAW_MAIL_ENCRYPTION_KEY=$(python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())")

echo "WEBHOOK_SHARED_SECRET=$WEBHOOK_SHARED_SECRET" >> .env
echo "RAW_MAIL_ENCRYPTION_KEY=$RAW_MAIL_ENCRYPTION_KEY" >> .env

3. Start services

# Full stack (gateway + Redis + ClamAV + Mailpit)
docker compose up --build

# Or just the gateway
uvicorn webhook_receiver.app:app --host 0.0.0.0 --port 8000 --reload

4. Send a test message

export SECRET="your-webhook-secret"

curl -X POST "http://localhost:8000/webhooks/sendgrid/inbound/$SECRET" \
  -F 'envelope={"from":"attacker@evil.com","to":["you@company.com"]}' \
  -F 'from=CEO Name <ceo-fake@gmail.com>' \
  -F 'text=URGENT: Wire $50,000. Verify: https://paypa1.com/login'

5. Run tests

python3 -m pytest tests/ -v
# 165 tests, all offline/local — runs in ~30 seconds
ℹ️ Dry-run mode
If RELAY_HOST is not set, the gateway computes all decisions and stores quarantine items but never actually relays mail. Safe for observation before pointing at live mail flow.

REST API Reference

Authentication

Inbound webhooks: secret embedded in URL path. Auth failures return 404 (not 401) — deliberate security design.

Admin endpoints: Authorization: Bearer <ADMIN_SHARED_SECRET> header required.

Health Endpoints

GET /healthz

Liveness probe. Returns 200 {"status": "ok"} if the process is alive.

GET /readyz

Readiness probe. Checks Redis, ClamAV config, relay config. Returns 503 if critical dependencies are down.

{"status": "ready", "redis": "ok", "clamav": "configured", "relay": "configured"}

Inbound Webhooks

POST /webhooks/sendgrid/inbound/{secret}

Receives inbound email from SendGrid Inbound Parse. multipart/form-data payload.

{
  "message_id": "msg_abc123",
  "action": "quarantine",
  "score": 95,
  "reasons": [
    "SPF hard fail",
    "DMARC fail under p=reject",
    "typosquat domain paypa1.com"
  ]
}

Also available: POST /webhooks/mailgun/inbound, POST /webhooks/ses/inbound, POST /webhooks/postmark/inbound, POST /webhooks/m365/inbound, POST /webhooks/google/inbound

Admin: Quarantine

GET /admin/quarantine

List all pending quarantine items. Requires bearer token.

POST /admin/quarantine/{id}/release

Release a quarantined message. Relays the original, unmodified message. Operator identity recorded in audit log.

curl -X POST http://localhost:8000/admin/quarantine/q_abc123/release \
  -H "Authorization: Bearer $ADMIN_SHARED_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"resolved_by":"analyst@company.com","note":"false positive"}'
POST /admin/quarantine/{id}/reject

Mark as reviewed; message stays on disk. Implements the "avoid blind dropping" design rule.

Module: auth_checker

Implements the gateway's full authentication stack. All checks run on every message and contribute score_delta values to the decision engine.

Checks

CheckImplementationScore on Fail
SPFRFC 7208, own evaluator+30 (fail) / +15 (softfail)
DKIMdkimpy+30 (invalid) / +15 (none)
DMARCDNS fetch + identifier alignment+10–+50 depending on policy
ARCValidates ARC-Seal chainMitigates SPF/DMARC if valid
BIMIDNS fetch, VMC validationSoft trust signal (no score delta)
FCrDNSPTR → A forward confirmation+15
MTA-STSPolicy fetch + header check+20 (enforce_failed)
IP ReputationDNSBL (Spamhaus ZEN)+15–+30
DKIM Key PolicyAlgorithm/key-length check+5–+15
Sender BaselineHistorical domain/IP tracking+10–+20 (first contact)
⚠️ Known Limitation
DMARC org-domain resolution uses a naive last-two-labels heuristic — wrong for multi-label ccTLDs like .co.uk. Replace with publicsuffix2/tldextract before processing such domains.

Usage

from auth_checker import run_auth_checks

verdict = run_auth_checks(
    raw_message=raw_bytes,
    client_ip="203.0.113.5",
    envelope_from="sender@example.com",
)
print(verdict.score_delta)  # e.g. 65
print(verdict.reasons)      # ["SPF hard fail", "DMARC fail under p=reject"]

Module: decision_engine

Aggregates stage scores and applies enterprise policy layers to produce a final routing decision.

Decision Logic

total = sum(stage.score_delta * weight for stage in stages)
       + feedback_adjustment
       + vip_score_boost
       + campaign_boost

if block_rule: action = QUARANTINE
elif allow_rule and no_malware: action = FORWARD
elif total >= quarantine_threshold: action = QUARANTINE
elif total >= warn_threshold: action = WARN_AND_STRIP
else: action = FORWARD

Policy Layers

LayerFileDescription
Per-tenant thresholdstenant_config.pyOverride warn/quarantine thresholds per tenant
Stage weightstenant_config.pyAmplify or reduce a stage's score_delta per tenant
Allow / block rulesallow_block.pyPrecedence overrides for known good/bad senders
VIP protectionvip_policy.pyScore boost + lowered threshold for executive impersonation
Campaign clusteringcampaign_clustering.pyBoost score when same content seen across many senders
Feedback loopfeedback_loop.pyAdjust score based on analyst release/confirm history
Shadow modeshadow_mode.pyA/B test experimental rules without affecting routing

Module: delivery

Acts on the routing decision. Three delivery paths, plus DLP, retroactive zap, and user-reported phishing.

Delivery Paths

ActionBehavior
FORWARDRelay raw message as-is via SMTP
WARN_AND_STRIPPrefix subject with [SUSPICIOUS], defang all links (hxxps[://]), strip attachments (replace with notice), then relay. If modification fails → escalate to QUARANTINE
QUARANTINEFernet-encrypt message, write to QUARANTINE_DIR, notify via Slack webhook or log

Quarantine Release vs Reject

ℹ️ Design Decision
Release delivers the original, unmodified message — the point of release is correcting a false positive, not re-delivering a defanged version of a message you just decided was safe. Reject marks as reviewed but keeps on disk — no blind dropping.

Module: multi_tenancy

Strict data isolation between tenants with per-tenant encryption keys and rate limits. Addresses the Critical STRIDE threat: Tenant A accessing Tenant B's quarantined mail.

Isolation Model

  • Separate quarantine directory per tenant: <QUARANTINE_DIR>/<tenant_id>/
  • Per-tenant Fernet encryption key — rotating Tenant A's key does not affect Tenant B
  • All quarantine API calls are scoped — cross-tenant access is impossible by construction
  • Rate limits are keyed rate:<tenant_id>:<client_ip> — one tenant cannot exhaust another's quota

MSP Admin View

MSPAdminView gives MSP operators a cross-tenant aggregate view. Requires msp_admin RBAC role. All MSP operations are audit-logged with operator identity.

Module: scalability

Production Hardening Checklist

Secrets

  • Generate strong WEBHOOK_SHARED_SECRET (32+ random bytes)
  • Generate Fernet RAW_MAIL_ENCRYPTION_KEY
  • Set separate ADMIN_SHARED_SECRET (never reuse webhook secret)
  • Store all secrets in Vault / AWS Secrets Manager — not in .env files
  • Rotate secrets on 90-day schedule

Network

  • Enable WEBHOOK_ALLOWED_SOURCE_IPS with provider CIDR ranges
  • Separate public ingress from admin routes via NetworkPolicy
  • Terminate TLS at the ingress controller
  • Place a WAF in front of the ingress (OWASP CRS + rate limiting)

Data Protection

  • Set QUARANTINE_DIR to an encrypted S3 bucket (not /tmp)
  • Set AUDIT_LOG_PATH to a path shipped to a log aggregator
  • Enable per-tenant encryption key isolation for multi-tenant deployments
